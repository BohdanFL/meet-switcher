# AST Search Mandate

When searching for code usages, analyzing architecture, or performing refactoring in this project, **YOU MUST NOT** use basic text search tools like `Select-String`, `grep`, or `findstr`.

**YOU MUST ALWAYS** use `ast-grep` for TypeScript code navigation.

## Usage Guidelines
- **Command:** Use `npx ast-grep run` (do not use the deprecated `sg` alias).
- **PowerShell Escaping:** Because the OS uses PowerShell, **ALWAYS wrap your `-p` and `-r` patterns in single quotes (`'`)**. Do not use double quotes (`"`), as PowerShell will attempt to evaluate ast-grep's `$` meta-variables as empty system variables, causing the search to fail silently.
- **Language Flag:** Always specify the language flag explicitly to avoid parsing errors: `-l ts`.

## Cheat Sheet for Meta-Variables
- `$A` : Matches a single AST node (e.g., a variable, a number).
- `$$$ARGS` : Matches multiple contiguous nodes (e.g., arguments in a function call, statements in a block).

## Examples
- **Find a function call:** 
  `npx ast-grep run -p 'console.log($$$ARGS)' -l ts src`
- **Find a specific structural pattern (e.g., timers):** 
  `npx ast-grep run -p 'setTimeout(() => { $$$BODY }, $TIME)' -l ts src`
- **Mass Refactoring (Rewrite):** 
  `npx ast-grep run -p 'oldFunction($A)' -r 'newFunction($A)' -l ts -U`

## Rationale
This rule exists to protect the LLM context window from token bloat and noise generated by false-positive textual matches. Structural search guarantees semantic precision.
